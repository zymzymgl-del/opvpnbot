# Отдельный бот техподдержки OPVPN

Проект отделён от основного репозитория OPVPN. В нём есть Telegram-бот на aiogram 3,
собственная SQLite-база переписки и тикетов, ИИ-диспетчер на DeepSeek API через
совместимый с OpenAI Python SDK и ограниченный реестр инструментов.

## Состояние

ИИ уже подключается к DeepSeek API и умеет понять обращение, задать уточняющий вопрос или
передать тикет специалисту. При заданном `OPVPN_DB_PATH` он может read-only прочитать
последние заказы, сохранённое состояние оплаты и состояние подписок пользователя.
Если также заданы `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`, он проверяет все связанные
с заказом платёжные ID прямыми GET-запросами к ЮKassa. DeepSeek получает только статусы,
суммы и даты, без ID платежей и учётных данных.
Также он проверяет, записан ли ключ для выбранной подписки, не читая само значение.
Это не проверка клиента в VPN-панели: для неё подготовлен отдельный внутренний API-контракт,
но endpoint пока не создан. Проверка статуса в ЮKassa выполняется только при запросе
пользователя и настроенных учётных данных. Повторная выдача отключена.

## Запуск локально

Требуется Python 3.12 или новее.

```powershell
Copy-Item .env.example .env
# Заполнить SUPPORT_BOT_TOKEN, SUPPORT_ADMIN_IDS и DEEPSEEK_API_KEY;
# для чтения заказов также задать OPVPN_DB_PATH
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m support_bot.main
```

Каждый специалист должен сначала открыть бота и нажать `/start`, иначе Telegram не
разрешит ему получать личные уведомления.

## Команды

Пользователю:

- `/start` — начать обращение;
- `/help` — подсказка;
- `/delete_me` — удалить переписку и все свои тикеты.

Администратору (ID должен быть указан в `SUPPORT_ADMIN_IDS`):

- `/tickets` — список открытых обращений;
- `/reply ID текст` — ответить пользователю;
- `/close ID` — закрыть обращение.

Ключ БД отдельный: по умолчанию `data/support.sqlite3`; с базой основного VPN-бота
он не связан. История диалога, передаваемая ИИ, хранится до 30 дней; закрытые тикеты
автоматически удаляются через 180 дней. Команда `/delete_me` удаляет локальные данные
пользователя сразу; она не удаляет сведения, ранее отправленные внешнему ИИ-провайдеру.

## Архитектура

- `support_bot/core` — типы, интерфейсы модели и backend, политика инструментов,
  ограниченный цикл обработки. Повторная выдача подписки выключена по умолчанию.
- `support_bot/providers/deepseek_model.py` — асинхронный DeepSeek adapter через
  OpenAI-совместимый API; серверный
  Telegram ID не передаётся модели, а текст пользователя отправляется для обработки.
- `support_bot/opvpn_readonly.py` — отдельный SQLite-адаптер с `mode=ro` и
  `query_only`; выбирает только данные аккаунта по Telegram ID из доверенного контекста.
- `support_bot/backend.py` — единственный исполнитель инструментов; реализует тикеты,
  а также чтение заказов, статуса оплаты и подписок при настроенном `OPVPN_DB_PATH`.
- `support_bot/handlers.py` — Telegram-обработчики пользователей и админов.
- `support_bot/storage.py` — собственная SQLite-база и долговременный inbox.
- `support_bot/main.py` — запуск aiogram с long polling.

Для Telegram выбран aiogram, потому что основной OPVPN-проект уже использует его,
а значит можно сохранить общий асинхронный стиль, Router и middleware. Библиотека
полностью асинхронная и обновляет поддержку Bot API; `python-telegram-bot` тоже
асинхронная, но отдельного преимущества для этого проекта не даёт.

DeepSeek предоставляет OpenAI-совместимый Chat Completions API. Здесь используется
официальный Python SDK в асинхронном режиме с адресом `https://api.deepseek.com`,
а модель по умолчанию — `deepseek-flash`. История function calls сохраняется в нашей
SQLite и возобновляется после перезапуска. Ключ и имя модели задаются через
`DEEPSEEK_API_KEY` и `DEEPSEEK_MODEL`.

Telegram-обработчики не обращаются к данным OPVPN напрямую: доступ идёт через
backend-адаптер с проверкой владельца и ограниченной проекцией чувствительных данных.

## Read-only интеграция аккаунта OPVPN

Подробная настройка, состав возвращаемых данных и границы доступа описаны в
[`docs/OPVPN-READ-ONLY-INTEGRATION.md`](docs/OPVPN-READ-ONLY-INTEGRATION.md). Пока
`OPVPN_DB_PATH` пуст, инструменты чтения скрыты от модели. Сохранённый статус заказа
не является live-проверкой у платёжного провайдера, а статус подписки — проверкой
доступности VPN-панели.

Проверка клиента в 3x-ui требует отдельного endpoint в основном OPVPN. В отдельный бот
нельзя помещать токен панели: он даёт полный административный доступ. Сейчас клиент
такого внутреннего endpoint находится в `support_bot/panel_status_client.py`; он принимает
только ограниченный ответ и не включается, пока не настроены
`OPVPN_PANEL_STATUS_API_URL` и `OPVPN_PANEL_STATUS_API_TOKEN`. Контракт описан в
инструкции по интеграции.
